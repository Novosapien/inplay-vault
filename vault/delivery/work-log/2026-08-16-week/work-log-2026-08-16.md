## The five things that matter

### 1. The engines met real games, and real games won

`inplay-market-maker` · `inplay-sportradar-service` · `inplay-fix-gateway-go`

**Why it matters** — a synthetic feed never produced these faults. Two game nights did.

**Market maker** — the CA/CB fix set
- **What** — a numbered programme of six fixes, not a list of unrelated branches
- **Closed** — the defects the 13 and 14 August games exposed
- **Result** — the engine keeps a game's opening price across a restart, refuses to cross
  a live market, and heals its own orders at boot
- **Speed** — it processes venue messages about **28 times faster**

**Sportradar service** — eight same-night corrections
- **What** — six correctness fixes to the market-maker publisher alone
- **Also** — post-game polling and cache-lifetime work
- **New** — the service finds live games by itself, instead of waiting for a person to
  type a game id

**FIX gateway** — four permanent-wrong states removed
- **What** — four ways an order or a price could stay wrong for ever

### 2. The system stopped stating more than it could prove

`inplay-app` · `inplay-admin-panel-trading`

**Why it matters** — both front ends invented data when they had none. A user and an
operator each saw a confident number that was not true.

**The app**
- **Symptom** — it generated a plausible order book when it had no data
- **Fix** — a price, a book, a chart or a day change now comes from the venue, or the
  screen says it has no data

**The admin panel — 14 August**
- **Symptom** — the engine held game-bound books LIVE and filled orders on them, while
  every Game chip read OVERNIGHT
- **Cause** — a flushed Redis cache in the Sportradar service; two redeploys removed the
  team map, so the board join returned nothing
- **Why that broke it** — the absence of the board outranked the presence of the engine

**The admin panel — 15 August, same symptom, different cause**
- **Symptom** — the same false OVERNIGHT on six live preseason books
- **Cause** — the board had recovered, but the cached regular-season schedule holds no
  preseason games, so it returned each team's September opener
- **Why that broke it** — a fixture weeks away beat live engine truth
- **Fix** — precedence made explicit: engine state outranks the schedule

### 3. The market maker starved the retail order feed

`inplay-trading-service` · `inplay-market-maker` · `inplay-app`

**Why it matters** — this is the clearest cross-service fault of the week. A house engine
and a retail user competed for one channel, and the user lost.

**The starvation**
- **Symptom** — real users saw their own order updates minutes late
- **Cause** — the market maker flooded the shared event queue
- **Frequency** — it happened **twice**
- **The other side** — the app records the same fault: order pushes ran minutes behind,
  which left the trade ticket on a stale side

**Two problems sat alongside it**
- **Prices ran up to 40 minutes behind the venue** — the market feed committed one
  message at a time
- **Users could not buy at the market price** — the venue accepts limit orders only, so a
  synthetic market order had to be built

### 4. The gateway filled its disk and both venue sessions dropped

`inplay-fix-gateway-go`

**Why it matters** — this is the only unplanned outage in the week's record.

**The 15 August outage**
- **Symptom** — both FIX sessions went down; the market maker had no venue connection
- **Duration** — about **one hour and forty minutes**
- **Cause** — the VM reached 100% disk
- **Fix** — logs archived, daily rotation installed
- **Prevention** — the storage rules written into the repository, so the same fault
  cannot repeat unseen

## Open risks

Each one is a decision, not a bug. All carried forward from the service files.

- **A dated deadline — 27 August.** `trader-lite` users reach the leaderboard endpoints,
  so non-US users will appear on the payout board when secondary opens, unless the
  separate global board ships first. The only dated item in the week's record.
- **`inplay-sportradar-service` `origin/main` is twelve days stale.** Everything from
  12 August sits on `dev` and `testing` only — live worker discovery and hardening, all
  six publisher fixes, cache lifetimes, the preseason schedule change, win-probability.
  Deliberate for the 13 August go-live, not revisited since.
- **Most of the app's week has not reached users.** The no-fabricated-prices work, the
  performance fixes and the live-worker reads all sit on `prerelease`.
- **The market-maker boot healer is inert.** The gateway shipped `GET /orders/mm` and it
  is live in gateway `main`. The healer cannot use it because `MM_GATEWAY_OPS_URL` is unset.
- **A gateway deployed without `OPS_API_KEY` breaks the broker.** Mutating ops routes now
  require `X-Ops-Key`. An unset key returns 503 and disables those routes, including the
  buying-power call.
- **Three trading-service features are dark by default.** Synthetic market orders
  (`synth_enabled` false), realized-P&L leaderboard mode (`lb_realized_mode` false), and
  referral top-up in the app (flag-gated — its config file warns that flipping it before
  the scheduler exists leaves a user with a top-up nothing credits).
- **One observability contract is wrong.** The admin trading spec puts `activity_state` at
  the top level as one value for the bot. The market maker derives it per book. The panel
  cannot see which books are live.
- **`/sr/winprob` takes no `season_type`.** Preseason ids never reach it. The app fills the
  gap client-side, capped at 20 probes, and retires the workaround when the endpoint
  learns `season_type`. That ask sits with the service team.
