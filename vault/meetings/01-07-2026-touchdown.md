### **Summary**

The meeting reviewed landing page improvements and app features alongside CRM integration and app store launch strategies.

**Web and app enhancements**  
The team reviewed navigation improvements for the landing page and demonstrated new features like the referral dashboard and pre-launch application version.

**Security and CRM strategy**  
Security risks necessitated the decision to share a Test Flight build for external demos instead of a Progressive Web App. Marketing integration strategies were aligned for data collection.

**Launch and market strategy**  
Plans were finalized for the application store submission process, including contingency options using web-based trading if approval is delayed. A follow-up meeting was scheduled for market pricing.

### **Decisions**

## Aligned

* **Mobile landing page button placement** Login and sign-up buttons are to be added to the top of the mobile trading challenge landing page.

* **Referral multiplier data source** Referral multipliers are to be updated to align with the data on the referral sheet.

* **College stadium images inclusion** College stadium images are to be included as a feature in the application.

* **AI-generated research for upsides and risks** AI tools will be used to research, aggregate, and populate criteria for the 'upsides' and 'risks' sections on the IPO page.

* **Leaderboard display order** The leaderboard will display users in alphabetical order prior to performance-based data becoming available.

* **Reloading criteria for IPO shares** Users are permitted to reload their balance if their net liquidating value falls below $25,000.

* **Demo delivery strategy for external parties** The Test Flight version of the application will be used for external demos, populated with dummy data to prevent exposure of proprietary underlying code.

* **HubSpot data mapping strategy finalized** The team will adopt a strategy of collecting and mapping all available application data points into HubSpot rather than pre-selecting specific fields.

* **Volatile data excluded from HubSpot** Real-time, volatile data fields, such as P\&L, are excluded from HubSpot mapping to prevent excessive update requests and database strain.

* **Maximum user communication frequency set** User outreach frequency is capped at a maximum of twice per week to maintain engagement and prevent spam.

* **Web-based trading contingency plan confirmed** A web-based trading application is adopted as the official contingency plan for the platform launch in the event of mobile app store rejection.
