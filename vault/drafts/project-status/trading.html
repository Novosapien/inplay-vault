Trading execution (tZERO) IN BUILD

The launch non-negotiable: live for the NCAA IPO on 22 August

Where it stands

The full map of every trading-infrastructure component was completed on 23 July. The order path to tZERO's matching engine is standing: a dedicated FIX gateway connected to tZERO's QA environment inside a locked-down private network, load-tested for concurrent volume. The named remaining items on the execution path are cancel and cancel-replace, plus fill notifications in the app.

Delivered

  • FIX gateway built, then rebuilt for high concurrency; two of the four tZERO session types (order entry, market data) implemented and exercised against tZERO QA.
  • Private network (VPC) stood up and connected to tZERO; load testing reported fast.
  • Wallet ownership resolved with tZERO: tZERO owns the trading wallet and real-time P&L; InPlay tracks the referral wallet and builds the buying-power ("synthetic broker") layer.
  • Order model settled: everything is a limit order (the venue's constraint); market orders are delivered as a synthetic "price-through" order crossing several levels.
  • Testing approach agreed: Sportradar simulation replays of past games run several times a day, checked from both the user side and the market-maker side — no need to wait for live games.

In flight

  • Cancel and cancel-replace — the two named to-dos from the 23-07 infrastructure map. tZERO does not support cancel-replace natively, so the gateway sequences cancel + new order.
  • Notifications — fill alerts are part of the launch remainder.
  • Buying-power flow — API proposal with tZERO for topping up buying power from the referral wallet (in place of a daily file).
  • Remaining gateway sessions (indications-of-interest, drop copy) for full book visibility and independent fill reconciliation.

Open with tZERO

  • Scope confirmation: the precise split of what tZERO manages for the simulated challenge — partly resolved (wallets, P&L), formal confirmation outstanding.
  • Market-maker account permissioning in QA (the synthetic entity with effectively unlimited buying power).
  • Self-match prevention behaviour — matters because two InPlay house accounts (IPO seller and market maker) will interact with the same books.
  • Cash-wallet host for real payouts (tZERO or a third party).
  • Shorting mechanics business requirements (with Troy).

Next

  • Finish cancel/cancel-replace and notifications.
  • Daily simulation replays as the standing test harness through August.
  • Full-dress rehearsal on tZERO QA in the week of 17 August: IPO → close → inventory hand-off → live quoting.
